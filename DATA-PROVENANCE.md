Construction and sources. The frozen v17 v3 list supplied 72,405 phone-keyed rows. Its v18 successor used Overture records, Serper searches, and Haiku 5.5 model searches. Version 19 continued from that exact successor: one coordinator submitted 9,830 distinct eligible phones through Anthropic Message Batches and added 1,209 accepted websites and 829 emails while preserving existing nonblank values. Version 20 reconciled a separate 100-record research set using reviewed identity rules: 27 matched existing companies and 73 became new rows. Seven matched companies gained previously blank websites. Research websites entered as “needs_review”; two conflicting existing website values were retained.

Validation. For the v19 additions, model answers were candidates. Page-verification code rejected directory, social, and private-network destinations and required fetched content showing the phone plus company-name/domain evidence. A recorded network-disabled replay checked the 1,209 accepted website decisions against retained inputs. That proof does not cover every inherited website or the v20 research additions. Recorded checks bind inputs and outputs by SHA-256, test database integrity, compare database/CSV/Excel/browser rows, and check preservation of prior nonblank values. Frozen inputs and scripts support rebuilding v19 and v20 without repeating searches. Complete pre-v17 reconstruction is unavailable.

Process and agents. Codex and Claude sessions coordinated research, implementation, review, and reconciliation; Haiku 5.5 low-effort requests supplied search candidates through the Batch API. The v19 run used one-item and three-item gates before 30 disjoint queue partitions—not 30 proven simultaneous agents. Its controller recorded intent, acceptance, results, and usage to prevent new duplicate submissions. The v18 report records 66 earlier duplicate submissions; the v19 report records zero new duplicates. Code applied the v19 website-proof rules; reviewed identity rules governed the separate v20 merge.

Architectural limits. Six rows lack phones; one phone is shared by two differently named businesses. Phone is indexed but not unique, and the public table has no stable company identifier. Raw trade and locality labels need normalization. Detailed evidence is stored separately; complete row-level provenance is not established for every inherited record. A later revision should preserve frozen inputs, introduce stable company identities, retain disputed links and evidence, and reconcile accepted or uncertain search claims before any resubmission. Website presence and email presence do not establish current contact validity.

## Reproduce v19 without new searches

Use a checkout with the **local Rocket Nation `production/` tree intact**. The public website repository alone is insufficient because it deliberately excludes the private raw responses and source captures. From `C:\Users\geral\dev\Rocket-Nation`, run:

```powershell
python production/verification/haiku-continuation-20261030/rebuild-v19-offline.py
```

The script checks the frozen v18 database hash, capture input hashes, page-body hashes, offline replay receipt and every preserved prior value. It rebuilds database and CSV in a temporary directory, checks the v19 database hash `2f57741a60199c05e5cde128a5e2ef8cf8c7e9dbfe71bd894f51b0c0d84abb9e` and CSV hash `f958ce4da7752bb99d16e4ed51f70cea0eb0cb32b3a4622b2fab70c3dc932064`, and removes the temporary files. It makes no network call and does not overwrite a deliverable. A successful run prints `exact_rebuild_passed: true`. If a dependency is missing or a hash differs, it fails; do not substitute a fresh network result or an older baseline. The rebuild script itself is retained in this permanent verification folder and copied into the private data repository with this guide. The final capture is about 1.4 GB and is retained locally in `production`; the private repository tracks the smaller provider receipts but does not contain every fetched page body.

This exactly rebuilds the **frozen v19 input to v20** from frozen v18 and retained v19 evidence. Fresh web searches cannot be expected to recreate the same responses, and deleted pre-v17 data cannot be reconstructed byte for byte. To audit the verification decision itself, inspect the retained `offline-publication-replay.json`, `inputs-manifest.json`, `results.jsonl`, page bodies, and `support/offline-replay.py`.
